# Migrating to libnmo 0.2.0

Version 0.2.0 prioritizes lossless parsing and safe write-back. Public schema
state is not source-compatible with 0.1.0 where parallel serialized lanes were
replaced by records.

## References

Use `nmo_ref_t` when a schema value is an object reference:

```c
nmo_ref_t ref;
nmo_status_t status = nmo_ref_read(chunk, &ref);
if (status == NMO_OK && ref.state == NMO_REF_RESOLVED) {
    use_object(ref.id);
}
```

`raw_id` is retained for unresolved values. `nmo_ref_write()` maps a resolved
runtime ID to a file ID and writes `raw_id` unchanged for every other state.
High-level graph and query code should consume only `NMO_REF_RESOLVED` values.

Grid layers now use `nmo_grid_state_t.layers`, whose elements are
`nmo_grid_layer_t { nmo_ref_t ref; nmo_chunk_t *chunk; }`. The old
`layer_ids`/`layer_chunks` fields have been removed.

`nmo_behavior_ref_t` is the corresponding short public record name for Behavior
reference/chunk lanes.

## Recoverable load failures

Attach caller-owned diagnostics to the load options:

```c
nmo_load_diagnostics_t diagnostics;
nmo_load_diagnostics_init(&diagnostics);
nmo_load_options_t options = nmo_load_options_default();
options.diagnostics = &diagnostics;
/* load using options */
nmo_load_diagnostics_destroy(&diagnostics);
```

A recoverable schema error clears the decoded state, retains the original chunk,
and continues scanning. `NMO_LOAD_STRICT` reports
`NMO_ERR_VALIDATION_FAILED` after all recoverable object errors have been
collected. Truncated top-level files, allocation failures, and internal errors
still stop immediately.

## Validation and normalization

`nmo validate structure` and `nmo validate all` include load diagnostics.
`nmo validate references` reports dangling references. To remove invalid scalar
references and invalid array records explicitly, save to a different path:

```text
nmo validate references input.nmo --normalize -o normalized.nmo
```

Normalization never overwrites the input and keeps valid record order.

## InterfaceChunk

Sectioned layouts preserve section presence and raw tagged mapping fields.
Code that authors a new sectioned layout can omit
`NMO_INTERFACE_FORMAT_SECTION_PRESENCE` to request the default section set. Data
parsed from a file carries that flag and therefore writes only sections present
in the input.
